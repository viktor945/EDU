# STEPLine EDU — передача программисту

Архив содержит весь исходный код опубликованной версии, lockfile зависимостей, SQL-миграции, статические иллюстрации, Excel-шаблоны и тесты. Это исходники, а не дамп работающей базы.

## Что работает в этой версии

- Четыре типа учреждений с отдельными данными, темами, разделами и доступами.
- Публикация контента, расписание, ученики и преподаватели, файлы, календарь, баннеры и режим ожидания.
- Русский, казахский и английский интерфейсы админки; выбранный язык — исходный для заполнения карточек. Оригинал сохраняется при смене языка редактирования. Нижние вкладки позволяют редактировать текст и файл двух других языков.
- 204 шаблона XLSX: 68 разделов четырёх типов учреждений × 3 языка. Папки `public/templates/<тип>/<RU|KZ|EN>/`. Старые пути шаблонов сохранены для совместимости.
- Текст слайда заставки ограничен 270 символами. Бегущая строка имеет независимую скорость и лимит 10 000 символов.
- Офлайн-показ публичного портала и `/screen/<id>` после первой полной онлайн-загрузки. Синхронизация раз в 240 секунд, сразу при восстановлении сети; локальная публикация также уведомляет открытые вкладки через BroadcastChannel.

## Среда выполнения и перенос

Это React 19 / TypeScript / Vinext-приложение, сервер которого сейчас работает как **Cloudflare Worker**, а не обычный Node.js/Next.js сервер. Простого копирования папки на VPS и `npm start` недостаточно для промышленного переноса.

Основные точки подключения:

| Часть | Сейчас | Что подключить на своём сервере |
| --- | --- | --- |
| HTTP/SSR | `worker/index.ts`, Vinext, `vite.config.ts` | Совместимый Worker runtime либо серверный адаптер Vinext/перенос API на выбранный backend |
| База | `env.DB`, D1 `.prepare().bind().first()/all()/run()/batch()` | Адаптер SQLite либо миграция SQL и запросов на PostgreSQL |
| Файлы | `env.BUCKET`, R2 `.get()/.put()/.delete()` | S3/MinIO либо безопасное файловое хранилище с тем же контрактом |
| Авторизация | Доверенные identity headers платформы Sites | Собственная проверка сессии/SSO, вход, приглашения и выход |
| Автоперевод | Google Cloud Translation | Серверный `GOOGLE_TRANSLATE_API_KEY` и включённый Cloud Translation API |

`build/cloudflare-workers-shim.ts` читает bindings из `globalThis.__STEP_EDU_RUNTIME_ENV__`, который устанавливает Worker. Это удобная граница для адаптера, но она не реализует базу, хранилище и Node HTTP-сервер сама по себе. `db/schema.ts` и последовательные `drizzle/*.sql` содержат схему. Автоматические миграции демонстрационного контента находятся в `app/content-seed.ts` и `app/content-organization.ts`; оцените их перед подключением реальных данных.

## Локальный старт для разработки

Нужны Node.js >= 22.13, npm и Linux (скрипты сборки используют GNU timeout и flock).

```bash
npm ci
npm run dev
# проверка типов и сборка
npx tsc --noEmit
npm run build
node tests/experience.cjs
node tests/content-integration.cjs
node tests/offline-and-languages.cjs
node --test tests/rendered-html.test.mjs
```

Vite/Cloudflare plugin эмулирует локальные D1/R2 bindings. `.openai/hosting.json` содержит настройки текущего Sites-проекта; не используйте его идентификатор для новой независимой публикации. Идентификаторы новых ресурсов и домен задайте в вашей конфигурации. Локальная база и bucket не содержат опубликованных клиентских данных.

## Данные, которые нужно перенести отдельно

Существующие учреждения, сотрудники, роли, профили устройств, материалы и настройки хранятся в D1. Загруженные клиентами фотографии/документы — в R2. Они **не включены** в исходный архив. Экспортируйте базу и объекты через учётную запись текущего хостинга. Сохраните идентификаторы `school_id`, записей и файлов, а также `object_key`, чтобы ссылки и языковые версии не потеряли связь. Секреты, токены, API-ключи, cookies и локальные runtime-каталоги в архив не включаются.

## Авторизация и границы доступа

`app/chatgpt-auth.ts` и `app/access-policy.ts` сейчас доверяют `oai-authenticated-user-email`, который добавляет хостинг. На своём сервере нельзя доверять такому заголовку от браузера: удаляйте входящие identity headers и формируйте идентичность только после проверки серверной сессии. Создание учреждений проверяется на сервере и разрешено владельцу платформы. Сохраните серверные проверки каждого API, а не только скрытие кнопок.

Кнопка приглашения пока создаёт письмо в почтовом клиенте администратора. Автоматическая отправка, пароль/email/SMS восстановление и промышленное управление лицензиями требуют отдельных серверных интеграций. Не считайте демонстрационные лицензии платёжным или DRM-механизмом.

## Офлайн-показ на устройствах

Нужен HTTPS (localhost допускается при разработке) и браузер с Service Worker/Cache Storage. Назначьте устройство в админке, откройте его `/screen/<id>` и дождитесь завершения подготовки офлайн-копии. Первый запуск без интернета не поддерживается. Сохраняются опубликованные данные, языковые варианты, изображения, галереи, документы, баннеры и файлы слайд-шоу. После обновления файлов сохранённый набор данных меняется только после загрузки всех его файлов и страниц.

`app/offline-cache.ts` отвечает за сохранение и интервал; `public/portal-sw.js` — за выдачу сохранённых HTML/файлов/ресурсов; `scripts/build-offline-manifest.mjs` включает ресурсы production-сборки в офлайн-манифест. Админка, сессии и закрытые API не кэшируются для офлайн-редактирования. Не кешируйте их на reverse proxy.

При смене версии service worker обновите идентификатор статического cache и версию страниц в обоих файлах. Сначала дайте устройству загрузить новую версию с сетью. Офлайн-поддержка зависит от доступного места: приватный режим, очистка данных браузера и удаление кеша ОС могут удалить копию. Хранилище запрашивает persistent storage, но решение принимает браузер.

Отключённое устройство блокируется при следующей успешной проверке сервера (404). Во время отсутствия сети оно показывает последнюю сохранённую версию; мгновенно отозвать её без связи невозможно. Первая синхронизация может загрузить несколько мегабайт; далее скачиваются данные и новые файлы, существующие файлы переиспользуются.

## Развёртывание и режим киоска

Настройте HTTPS, постоянный диск/базу, резервные копии, лимиты файлов, журналирование, мониторинг и безопасное хранение ключа перевода. Сначала проверьте сохранение → публикацию → показ → перезагрузку без сети для всех четырёх типов учреждений. Проверьте ограничения каждой роли на уровне API.

Портал и service worker не блокируют системные жесты, выход из браузера или меню ОС. Для автозапуска и запрета выхода используйте управляемый kiosk mode Windows/Android, MDM/device owner и отдельный административный способ выхода. Эти ОС-настройки не заменяются JavaScript сайта.
